Setup

From a link to a working setup.

Paste a GitHub, GitLab or zip link, or a folder. The model reads the whole code base and works out the board, the chip and what it needs.

  • Finds the devices the code runs on, and matches them to what is on your USB ports
  • Choosing another branch reads the code base again: its use cases, devices and tools
  • For a board that is not public yet, your own documents come first
  • One setup bot, the only place you talk during the setup

Run on the board

Build, flash, check. One button.

Say what you expect; the board is built, flashed, reset and read, and the output is checked against your words.

  • How the board resets is detected from its setup: nothing to choose
  • The output shows as live graphs, a table, or the log with problems marked
  • When the board stays dark while its IDE works, the build and flash are made to match the IDE's
  • A fix is offered only when the output was wrong

Terminal

A command line that talks back.

The whole chat becomes a terminal in your code base. Commands run; plain words go to the model.

  • A failed command: its cause, why, the component, the fix and whether it is safe
  • /build, /flash, /run, /debug, /setup and more; /help lists them
  • Secrets in the output are masked
